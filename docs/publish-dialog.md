# Publish a game: runtime, release convention, and the "Open game" dialog

Date: 2026-09-09. Status: spec for build. Paths are relative to the monorepo root.
Code facts were verified against `apps/editor`, `packages/threepipe`, `backend`, and `game-gateway` on this date.
`backend/` and `game-gateway/` are owned by another agent. This spec lists what they must add. It does not edit them.

This spec covers three things:

1. The release convention for a published game.
2. The runtime that boots a game from a URL, `createGame({base, canvas})`.
3. The editor "Open game" dialog and the deploy client behind it.

## 1. Decisions

- Reuse the local `backend` and `game-gateway` workers. Do not copy teenybase again.
- The runtime is a file in the release, at `_blitz/runtime.js`.
- Each runtime version has one canonical R2 location: `blobs/<sha256 of runtime.js>`. A `runtimes` table maps version to sha256. Games reference the runtime by sha256. The deploy client never uploads the runtime.
- The deploy client generates `index.html`. Server-side synthesis comes later.
- The runtime version equals the editor version. The deploy client writes `blitz.version` into package.json on first deploy.
- The dialog prefills the slug, checks uniqueness, shows the 12 hour notice, offers "Copy prompt" for agents, and has one "Create live game" button. That button opens the live URL at once. The live URL shows a spinner until the first release lands.

## 2. What exists today

The full API contract, with error codes and a curl walkthrough, is in `docs/publish-api.md`, written by the backend agent. Until the routes attach to blitz.dev, `preview_url` uses the workers.dev path form `https://<gateway>/<slug>/`. The backend also has `DELETE /api/v1/games/:id` and deploy-token management routes. This spec does not use them.

Backend, `blitz-backend`, route `blitz.dev/api/*`. Auth header is `Authorization: Bearer <token>`.

| Route | File | Notes |
|---|---|---|
| `POST /api/v1/new-game/:slug?name=&source=` | `backend/src/routes/anon-games.ts:25` | no auth. 201 with `game_id`, `slug`, `name`, `state`, `expires_at`, `preview_url`, `deploy_token`, `claim_secret`, `claim_url` |
| `POST /api/v1/games/:id/blobs/missing` | `backend/src/routes/blobs.ts:10` | body `{hashes: string[]}`, max 2000. Returns `{missing: string[]}` |
| `PUT /api/v1/games/:id/blobs/:sha256` | `backend/src/routes/blobs.ts:43` | raw body, `Content-Length` required, R2 verifies the hash. 201 or 200 if present |
| `PUT /api/v1/games/:id/releases` | `backend/src/routes/releases.ts:36` | body `{files, message?}`. Verifies every blob. Activates at once |
| `GET /api/v1/games/:id/releases` | `backend/src/routes/releases.ts:84` | list with `active` flag |
| `POST /api/v1/games/:id/releases/:hash/activate` | `backend/src/routes/releases.ts:105` | rollback |
| `POST /api/v1/games/:slug/claim` | `backend/src/routes/claims.ts:31` | platform token plus `{secret}`. Clears `expires_at` |

Limits: 100 MiB per blob (`blobs.ts:8`), 500 MiB per game (`releases.ts:15`), 2000 files (`backend/src/utils/manifest.ts:23`). Anonymous TTL is 12 hours (`backend/src/utils/anon-constants.ts:3`).

Storage: blobs at `blobs/<sha256>` in bucket `blitz-games-blobs`. Manifests in D1 `releases.manifest_json`. Tables: `users`, `games`, `game_tokens`, `releases` (`backend/migrations/0000_initial.sql`). Expiry marks `cleaning`, cleanup deletes after 30 seconds, blobs stay (`backend/src/cron/`, `backend/BLOB-GC.md`).

Gateway, `blitz-game-gateway`, route `*.app.blitz.dev/*`. GET and HEAD only. Slug from host, `/` maps to `index.html` (`game-gateway/src/path.ts:33`). One D1 read for the game row, then the manifest, then R2 (`game-gateway/src/index.ts:61-90`). Headers: MIME, ETag equal to the hash, Range, `Cache-Control: public, max-age=60, must-revalidate`, nosniff (`index.ts:106-114`). No CORS. The same-origin design does not need it.

Gaps: no runtime exists. No editor code calls the API. Nothing generates `index.html`. An open game with no release returns 404 (`index.ts:68`).

## 3. Release convention

The container format is fixed by the backend:

- `files` maps a relative path to `{sha256, size, mime?}`. The hash covers only `files`. `message` stays outside the hash (`backend/src/utils/manifest.ts:6-15`).
- Path rules: no leading or trailing slash, no `//`, no `\`, no `.` or `..` segments, max 512 chars (`backend/src/utils/validation.ts:29-34`).

A game release must contain these entries:

| Entry | Source | Required |
|---|---|---|
| `index.html` | generated by the deploy client, section 4.3 | yes |
| `_blitz/runtime.js` | sha256 from the runtime registry, section 4.2 | yes |
| `package.json` | project root, with `blitz.version` | yes |
| `assets.json` | project root | yes |
| `main.js` | project root | yes |
| the main scene | path from `mainScene`, default `assets/main.scene.glb` | yes |
| `*.script.js`, `*.plugin.js` | project root and subfolders | as listed in package.json |
| `assets/**` | project folder | yes |
| `AGENTS.md`, `icon.svg` | project root | optional |

Exclude `.blitz/`, `.git/`, `node_modules/`, `dist/`, and dotfiles.

Set `mime` for `html`, `js`, `json`, `gltf`, and `glb`. The gateway MIME table wins otherwise (`game-gateway/src/mime.ts`). A manifest `mime` always wins over the table.

Example:

```json
{
  "files": {
    "index.html":                 {"sha256": "…", "size": 1180,    "mime": "text/html"},
    "_blitz/runtime.js":          {"sha256": "…", "size": 2100000, "mime": "text/javascript"},
    "package.json":               {"sha256": "…", "size": 410,     "mime": "application/json"},
    "assets.json":                {"sha256": "…", "size": 96,      "mime": "application/json"},
    "main.js":                    {"sha256": "…", "size": 220,     "mime": "text/javascript"},
    "PlayerController.script.js": {"sha256": "…", "size": 1320,    "mime": "text/javascript"},
    "assets/main.scene.glb":      {"sha256": "…", "size": 84000},
    "assets/tree.glb":            {"sha256": "…", "size": 310000}
  },
  "message": "v1"
}
```

## 4. Runtime

### 4.1 Bundle

- Add a second build input to `apps/editor/vite.config.ts`. Output name is fixed: `runtime.js`. No content hash in the name.
- The bundle exports `createGame` and re-exports everything from `threepipe`, `uiconfig.js`, and `ts-browser-helpers`. The editor already re-exports these in `apps/editor/src/import-map/threepipe.ts`.
- The bundle includes the runtime plugin set. Each `@threepipe/*` plugin package has exactly one bare external, `threepipe`, so bundling works.
- The version is the editor version from `apps/editor/package.json`.
- The release pipeline uploads `runtime.js` once per version through the admin route in 4.2. The editor R2 bucket sits on a different Cloudflare account than the games workers, so the upload must go through the backend.

### 4.2 Runtime registry

Backend additions:

- Table `runtimes(version TEXT PRIMARY KEY, sha256 TEXT NOT NULL, size INTEGER NOT NULL, created_at TEXT NOT NULL)`. New migration in `backend/migrations/`.
- `PUT /api/v1/runtimes/:version`. Admin auth with a `RUNTIME_UPLOAD_TOKEN` secret. Raw body. Writes `blobs/<sha256>` with R2 checksum verification, then upserts the row. Returns `{version, sha256, size}`.
- `GET /api/v1/runtimes/:version`. Public. Returns `{version, sha256, size}` or 404.
- `PUT /api/v1/games/:id/releases` must accept a manifest whose `_blitz/runtime.js` sha256 is a registered runtime. The blob exists, so no code change is needed for that check. Optional stricter rule: reject a `_blitz/runtime.js` entry whose sha256 is not in `runtimes`.
- Blob GC must mark every sha256 in `runtimes` as a root. Update `backend/BLOB-GC.md`.

### 4.3 Generated index.html

The deploy client writes this file. `<version>` is `blitz.version`. Dependency entries mirror `apps/editor/src/utils/importMaps.ts:30-50`: `https://esm.sh/<key>@<version>?external=<all known keys>`.

```html
<!doctype html>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>{name}</title>
<script type="importmap">
{"imports":{
  "threepipe": "/_blitz/runtime.js",
  "three": "/_blitz/runtime.js",
  "uiconfig.js": "/_blitz/runtime.js",
  "ts-browser-helpers": "/_blitz/runtime.js"
  {dependency entries}
}}
</script>
<style>html,body,canvas{margin:0;width:100%;height:100%;overflow:hidden;background:#000}</style>
<canvas id="blitz-canvas"></canvas>
<script type="module">
  import {createGame} from '/_blitz/runtime.js'
  createGame({base: '/', canvas: document.getElementById('blitz-canvas')})
    .catch(e => { document.body.textContent = 'Failed to start: ' + e.message })
</script>
```

### 4.4 createGame({base, canvas})

`base` is a URL prefix. A second source type, a directory handle, can come later behind the same read-file adapter. The function returns `{viewer, project}`. The handler API for scripted input and tick stepping stays deferred.

Steps, in order:

1. Fetch `package.json` and `assets.json` under `base`. Reuse the parsers in `apps/editor/src/utils/project.ts:33-51` and `:240-338` as they are.
2. Create `ThreeViewer({canvas, ...config.viewer, plugins})`. Runtime plugins only: `EntityComponentPlugin`, `GBufferPlugin`, `CannonPhysicsPlugin`, `PopmotionPlugin`, `GLTFAnimationPlugin`, `GLTFMeshOptDecodePlugin`, the format loaders the project uses, and `HtmlUiComponent` as a component type. No dropzone, picking, transform controls, widgets, edit mode, snapshot, exporter, or Blueprint UI. Set `viewer.timeline.endTime = 0`.
3. Add one URL modifier before any load. `/blitz/@<id>/f.<ext>` becomes `base` plus `assets.json.files[id].path`. `/blitz/<path>` becomes `base` plus `<path>`. The editor has this hook commented out at `apps/editor/src/utils/ViewerInstanceManager.ts:362-369`.
4. Extract the nested-asset loader from `apps/editor/src/utils/AssetTracker.ts` with the editor flag off. Scenes store nested references as `userData.rootPath` in the `/blitz/@<id>/` form (`ViewerInstanceManager.ts:1015`).
5. Import each entry of `blitz.plugins`, then call `viewer.addPlugin`. Import each entry of `blitz.scripts`, then call `addComponentType` for every export with `ComponentType`. Extract the export walk from `apps/editor/src/utils/ScriptUtil.ts:470-574`. On a URL source, scripts are plain same-origin ES modules. Relative imports resolve natively. Bare imports resolve through the import map. No service worker.
6. Await all registrations. Then `viewer.load(sceneUrl, {importAsModelRoot: true})`. Await the nested loading promise.
7. `timeline.reset()`, `timeline.start()`, component plugin `start()`, physics `running = true`.
8. Import `main.js` and call `main({viewer})`. Route rejections to `onError`.

Ordering rules the engine forces:

| Rule | Proof |
|---|---|
| Register component types before the scene loads. Late registration destroys the placeholder and wipes its state. | `packages/threepipe/src/plugins/extras/EntityComponentPlugin.ts:392-399`, `:426`, `:570`; `components/Object3DComponent.ts:94-99` |
| Add every plugin before the scene loads. Config for a missing plugin is skipped without a warning. | `packages/threepipe/src/viewer/ThreeViewer.ts:1284-1299` |
| The scene root must carry `userData.rootSceneModelRoot`, or viewer config never applies. | `ThreeViewer.ts:1219` |
| The timeline loops every 2 seconds unless `endTime` is 0. | `packages/threepipe/src/utils/ViewerTimeline.ts:55`, `:66` |
| Updates run only after `timeline.start()` and the component plugin `start()`. | `EntityComponentPlugin.ts:183` |

Do not reuse `buildProjectBundleCode` in `apps/editor/src/utils/project.ts:340-541` or `apps/editor/src/player.ts`. Both are broken at the syntax level.

## 5. The "Open game" dialog

The button sits at the top right of the editor. It opens a dialog.

### 5.1 Entry states

- No entry for this project in `.blitz/deploys.json`: show the create form, section 5.2.
- An entry exists and `expires_at` is in the future: show the live URL, a copy button, the remaining time, "Open", and "Publish update". "Publish update" runs steps 4 to 8 of section 5.4 with the saved token.
- An entry exists and is expired: show "expired", then the create form with the old slug prefilled.

### 5.2 Create form

Fields and notices:

- **Slug.** Prefilled from `name` in package.json, slugified to the server rule: lowercase, digits, hyphens, 3 to 49 chars, no `--`, first and last char alphanumeric, not in the reserved list. The client mirrors `backend/src/utils/validation.ts:1-27` for instant feedback. The server stays the authority.
- **Availability.** Debounce 300 ms. Call `GET /api/v1/slugs/:slug`. Show "available", "taken", "reserved", or "invalid". Disable the create button unless available.
- **Expiry notice.** "This game expires in 12 hours unless you sign in and claim it."
- **Agent notice.** "An agent can create this for you." Next to it, a "Copy prompt" button. The prompt is not shown.
- **Create live game** button.

### 5.3 Copy prompt

The button copies this text. It contains no secrets. `<slug>` is the current slug field value.

```
Deploy the Blitz game in this folder to a live URL.
Read https://blitz.dev/agents.md and follow the Deploy section.
Use the slug "<slug>". If .blitz/deploys.json exists, reuse its deploy_token.
Otherwise create a new anonymous game. Report the preview URL when done.
```

The Deploy section of agents.md does not exist yet. See section 6.

### 5.4 Create live game

| # | Editor | Server |
|---|---|---|
| 1 | Open a blank tab synchronously inside the click handler. Keep the handle. | none |
| 2 | `POST /api/v1/new-game/<slug>?name=<name>` | 201 with token, secret, `preview_url`, `expires_at` |
| 3 | Write the entry to `.blitz/deploys.json`. Point the blank tab at `preview_url`. | gateway serves the spinner page |
| 4 | Walk the directory handle with the exclusions of section 3. Hash each file with SubtleCrypto SHA-256. | none |
| 5 | Write `blitz.version` into package.json if missing. `GET /api/v1/runtimes/<version>`. Add `_blitz/runtime.js`. | returns sha256 and size |
| 6 | Generate `index.html` from section 4.3. Hash it. Build the manifest. | none |
| 7 | `POST .../blobs/missing`. `PUT .../blobs/<sha256>` for each missing blob, four in flight. Show a progress bar. | R2 verifies each hash |
| 8 | `PUT .../releases` with `message: "initial"`. | activates the release |
| 9 | Show the live URL, a copy button, and the expiry time. | the spinner tab reloads into the game |

### 5.5 Spinner page

Gateway change in `game-gateway/src/index.ts:68`. An open game with no `active_release` returns a spinner page, not 404.

- Status 503. Headers: `Retry-After: 2`, `Cache-Control: no-store`, `X-Blitz-State: publishing`, nosniff.
- Body: a centered spinner, the text "Publishing your game", and a script. The script requests `/` every 2 seconds with `cache: 'no-store'`. When the response has no `X-Blitz-State` header, it calls `location.reload()`.
- An unknown slug still returns 404. An expired or cleaning game still returns 410.

### 5.6 `.blitz/deploys.json`

Gitignored. Add it to the gitignore template in `apps/editor/src/data/projectTemplates.ts`. Note the current template writes `./kite/...` paths without the leading dot. Fix that in the same change.

```json
{
  "games": {
    "<slug>": {
      "game_id": "…",
      "deploy_token": "tp_…",
      "claim_secret": "…",
      "preview_url": "https://<slug>.app.blitz.dev/",
      "expires_at": "2026-09-10 01:00:00",
      "last_release_hash": "…"
    }
  }
}
```

### 5.7 Edge cases

- Slug taken between the check and creation: the 409 returns the user to the slug field and closes the blank tab.
- Popup blocked: show the URL as a link in the dialog.
- Upload fails midway: the game exists with no release, so the spinner keeps polling. The saved token makes a retry safe. Blob uploads dedupe. An identical manifest returns 200.
- Backend 413: show the limit from section 2.
- Backend 429 or 503 lockdown: show "try again in a minute".
- Sign-in later: the saved `claim_secret` lets the editor claim every game in the file.
- Network loss during the walk or hashing: keep the dialog open with a retry button. Nothing was sent yet.

## 7. Build order

Two phases. Each phase ends with the tests of section 8 passing.

- **Phase A: runtime.** Build entry, `createGame`, and a sample project served by a static file server. Blocks everything else.
- **Phase B: publish path.** Editor deploy client and dialog. Backend and gateway additions run in parallel with the same contract.

## 8. Verification

Runtime:

- A Playwright test serves a sample project from a static server and calls `createGame`. It asserts that a component `update` ran, for example an object position changed. It asserts no console error contains `unknown component type`. It asserts a nested asset under `/blitz/@<id>/` loaded.
- The test fails when the URL modifier or the script registration step is removed.

Deploy client:

- Unit tests for slugify against the server regex and the reserved list, for manifest canonical order, and for the import map in the generated `index.html`.
- An integration test against `wrangler dev` for backend and gateway, in the style of `backend/test/integration/publish-flow.test.ts`. It creates a game, asserts the spinner page at `/`, uploads, publishes, then asserts `/` returns `index.html` and `/_blitz/runtime.js` returns the runtime bytes with `text/javascript`.

Backend and gateway:

- `GET /api/v1/slugs/:slug`: invalid, reserved, taken, and free cases.
- Spinner branch: open game with no release returns 503 with `X-Blitz-State`. Unknown slug returns 404.
- Runtime routes: `PUT` without the admin token returns 401. `GET` is public.

Manual, before any PR: run the create flow in the editor, watch the spinner turn into the game, press "Publish update", and reload the live URL.
